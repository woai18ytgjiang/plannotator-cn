# Plannotator 简体中文本地化：执行规范（所有成员必读）

仓库：`<你的仓库路径>`（Windows，Bun 1.3.14 已装好依赖，勿再 `bun install`）。
目标：把**面向最终用户**的英文界面文案就地改写为**简体中文**，让本地部署的 Plannotator 操作页面、通知/提醒、弹窗全部显示中文。

## A. 只改“展示给用户”的文案

**要翻译：**
- JSX 文本节点：`<button>Approve</button>` → `<button>批准</button>`
- 展示属性：`title=`、`placeholder=`、`aria-label=`、`aria-description=`、`alt=`、`label=`、`description=`、`tooltip=`、`heading=`、`emptyText=` 等
- 传给组件的可见文案 props（如 `label`、`title`、`description`、`text`、`message`、`helperText`、`confirmLabel`、`cancelLabel`、`emptyMessage`）
- `toast.success/error/info/warning/message("...")` 的文案
- 对话框标题/正文/按钮、空状态、错误提示、设置项名称与说明、键盘快捷键说明、菜单项、状态标签、占位文案
- `new Error("...")` 里会被展示给用户的文案（不确定时保留英文，在报告中注明）
- 模板字符串中的自然语言部分，保留 `${...}`：`` `Copied ${count} annotations` `` → `` `已复制 ${count} 条批注` ``

**绝对不要改：**
- 测试文件：`*.test.ts(x)`、`*.spec.ts`、`*.dom.test.*`、`tests/` 下任何文件（测试保持英文，翻译导致的测试断言失败由 Lead 统一处理）
- 注释、文档、README、`console.log/error` 的调试日志、`data-*` 属性、`id`、`name`、`key`、`className`、CSS 变量、URL/路由/API 路径、localStorage/cookie key、环境变量、命令行参数、命令行 usage/help 文本（CLI 由 Lead 单独处理）
- **被代码用作逻辑值的字符串**：例如 `status === "approved"`、`kind: "plan"`、`type: "comment"`、`role: "button"`、`action: "accept"`、事件名、agent 标识、provider id、emoji 短代码 —— 改了就坏功能。判断方法：如果同一字符串既用于显示又用于比较，**只改显示处**（或新增展示映射），不要改常量本身。
- Markdown/HTML 示例内容、代码块、文件名、路径、命令行示例、邮箱、URL。
- 品牌名与技术标识（见术语表第 1 节）。
- 不要重排代码、不要改格式、不要动 import 顺序、不要增删功能。

**判断依据：** 这个字符串会不会被最终用户在界面上看到？会 → 翻译。只在代码内部/日志/测试里 → 不翻。

## B. 保证代码不被改坏

1. 只改字符串字面量和 JSX 文本内容，不改任何代码结构。
2. JSX 里中文字符不需要额外转义；但注意保留原有的 `{" "}`、`&nbsp;`、换行与缩进。JSX 文本前后的空格若对排版重要，保留。
3. 引号：中文字符串里如需引号，统一用「」或中文引号，避免和外层 `'`/`"`/` 冲突。模板字符串里不要引入反引号。
4. 遇到 `dangerouslySetInnerHTML`、正则、i18n 参数、`split("...")`、`startsWith(...)`、`includes(...)`、`key={...}` 等上下文要格外小心——**这些不是展示文案**。
5. 每完成一批文件，运行对应包的 TypeScript 检查，确保没有新增错误（基线见任务说明）。
6. 不要启动 dev server、不要跑 `vite build`、不要 `git` 提交、不要改 `package.json`。Lead 统一构建验证。
7. 不要改动其他人负责的文件（写入范围见任务）。若必须跨范围修改，先报告给 Lead。

## C. 质量要求

- 用词严格遵循 `.tmp-i18n/GLOSSARY.md`。
- 中文要通顺、专业、简洁；不要机翻腔；不要中英混排过长（品牌名/技术词除外）。
- 同一文件内同类文案风格一致。
- 长说明文字可意译成自然中文，但不得丢失信息（尤其设置项说明、权限说明、安全提示）。
- 保留原文中的示例值、数字、变量。

## D. 验证与汇报

- 每完成一个文件/一批文件后，在任务的共享进度里更新（或最后统一汇报）。
- 结束时汇报：已翻译文件清单、大致翻译条数、未完成/跳过部分及原因、新增术语、发现的风险。
- 如中途发现某类字符串无法安全翻译，**保留英文**并在报告中列出，不要强行翻译。

## E. 优先级

1. 主界面一屏内可见的工具栏、按钮、标题、状态、空状态、通知（最高）
2. 对话框、弹窗、设置面板
3. 二级页面、设置项详细说明、帮助文本
4. 边角文案

同一文件尽量一次做完，避免半中半英；若文件极大（>200KB），可按“主界面区域优先”的顺序做，并在报告中说明剩余部分。
