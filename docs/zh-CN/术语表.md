# Plannotator 简体中文本地化：术语表（必须严格遵守）

目标：把面向用户的英文文案改写为**地道、简洁、专业的简体中文**。这是单语种本地化（直接把英文文案替换成中文），不引入 i18n 框架。

## 1. 品牌与专有名词（不翻译，保持原样）

Plannotator、Claude Code、Claude、Codex、OpenCode、Pi、Amp、Droid、Gemini CLI、Copilot CLI、Kiro、T3 Code、DeepSeek Harness、Cursor、VS Code、GitHub、GitLab、Bitbucket、Linear、Notion、Obsidian、Bear、Octarine、Tailscale、Cloudflare、MCP、WebMCP、ACP、API、JSON、HTML、CSS、Markdown、URL、CLI、Git、Jujutsu（jj）、Perforce（p4）、GitButler、PR、MR。

技术标识保持英文：文件名/路径/命令/环境变量/参数（如 `--staged`、`PLANNOTATOR_PORT`）、模型名（Sonnet 4.6、Opus、Haiku、GPT、Gemini）、按键名（Ctrl、Cmd、Shift、Alt、Enter、Esc、Tab、Space、Backspace、Delete）、代码块、URL、邮箱、emoji 短代码。

## 3. 翻译风格要求

1. **像原生中文产品**：不要逐词直译。例如 "Turn it on" → 「开启」；"Bring it up to date" → 「更新到最新」；"Nothing was run." → 「未执行任何命令。」
2. **按钮/菜单/标签用短动词短语**（2–6 字）：批准、拒绝、发送反馈、复制、设置、取消。
3. **说明句用完整、简洁的句子**，保留原意、语气自然；长段落可适当断句，但不得删减信息。
4. **中文标点**：正文用「，。：；！？」和「（）」；英文单词/代码两侧留空格（如「在 Settings 中」）。
5. **人称**：面向用户称「你」，避免「您」以外的敬语堆砌；系统主体称「Plannotator」「智能体」。
6. **数量与变量占位符**：保留 `{}`、`${}`、`%s`、`{count}`、`:name` 等占位符原样；复数形式（`{n} files`）改成「{n} 个文件」。
7. **不要翻译**：代码、路径、命令、键名、URL、品牌名；但字符串里的**全大写状态词**如果是展示给用户的（如 "LGTM"）可酌情处理，"LGTM" 建议保留或写「通过」。
8. **统一用词**：同一概念在全仓库用同一个中文词（以本表为准）；遇到表里没有的新术语，选择自然、简短、业内通用的译法，并在完成报告中列出新术语，便于其他成员统一。
